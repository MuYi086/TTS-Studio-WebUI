# 任务计划 3：接入 MOSS-SoundEffect 自动生成上下文音效

## 结论

可做，但应分两期。`~/github/TTS-and-VoiceDesign` 已在端口 `8312` 提供可直接返回 WAV 的 MOSS-SoundEffect v2.0 服务：`POST /v1/moss/soundEffect`，`prompt` 为非语言声效描述，`seconds` 可控且范围为 `(0, 30]`。它适合解决“素材库固定、短动作音效时长不合适”的问题。

当前 WebUI 已通过 `js/soundeffect-client.js` 调用 `8312/v1/moss/soundEffect`；当前 `sfx_plan` 以承载事件的对白为锚点，没有跨多条台词的持续环境声时间跨度。第一期只做可验证的单句前景音效；连续环境声、跨台词氛围和自动混音属于第二期，必须先扩充时间轴表达并复核导出语义。

本文件仅设计，不请求服务、不生成音效、不修改任何代码或项目数据。

## 已核对的接口与限制

后端接口的有效请求形态为：

```http
POST http://127.0.0.1:8312/v1/moss/soundEffect
Content-Type: application/json

{
  "prompt": "近距离，生锈的旧木门被缓慢推开，门轴连续发出低沉吱呀声，安静室内收音。",
  "seconds": 2.5,
  "num_inference_steps": 100,
  "cfg_scale": 4.0,
  "sigma_shift": 5.0,
  "seed": 0
}
```

返回是 `audio/wav`，不是 JSON。`prompt` 上限 2,000 字符，`seconds` 最大 30；模型不接收参考音频，也不生成台词。服务为“每请求启动一个 worker、生成后进程退出”的显存生命周期，并以共享 GPU 锁与现有 TTS worker 串行。因此前端不能并发提交几十条音效，也不能把它伪装成即时、无成本的点击操作。

本地依据：`soundEffect/README.md`、`soundEffect/声效提示词说明.md`、`api/soundeffect_api.py`。上游能力依据：[MOSS-SoundEffect v2.0 官方模型卡](https://huggingface.co/OpenMOSS-Team/MOSS-SoundEffect-v2.0)。

## 与当前时间轴的关系

当前工程的安全边界为：

- 类型只能是 `dialogue`、`bgm`、`bgImage`；不能新增独立 `sfx` 时间轴块。
- `dialogue.sfx` 当前只保存 `{ "name", "position" }`，其中 `position` 是对白裁剪后时长内的 0–1 比例；`break_duration` 不包含在这个比例中。
- 播放与离线导出都按该相对位置调度，音效与台词音量按既有乘法关系混合。
- SFX、BGM 和台词二进制均由 `UnitaleDB` 资产键恢复，工程导出还须携带可恢复的资产关系。

这决定了第一期音效必须写入对白计划的 `audioAssetKey`；不能把临时 `8312` URL、裸 Blob URL 或“模型提示词”直接当作可播放素材。

## 两期方案

### 第一期：单句前景音效（建议先做）

适用对象：关门、敲门、脚步、玻璃碎裂、拔刀、物体落地、短促机械声等一个可定位的非语言事件。

流程：

```text
已审核的 scriptLines
  → 生成全部或选中的 TTS 台词，取得实际时长
  → LLM 仅规划可听事件（不生成音频、不可编造已有素材名）
  → 用户审核/编辑音效 prompt、落点和时长
  → 单队列调用 8312
  → WAV 存入 UnitaleDB，并新建 SFX 库记录
  → 以现有 {name, position} 写回关联 dialogue
  → 统一试听、裁剪、导出
```

音效规划器输入应包含当前句、前后各一条、场景信息、实际对白时长、`break_duration` 与已有 SFX；它输出严格 JSON，供用户确认：

```json
{
  "items": [
    {
      "id": "sfx_plan_001",
      "line_id": "line_123",
      "kind": "foreground",
      "position": 0.72,
      "duration_seconds": 1.8,
      "prompt": "厚玻璃杯在木地板上摔碎，近距离传来一次清脆碎裂和短暂碎片滚动声。",
      "reason": "正文明确写到杯子摔碎",
      "confidence": "high"
    }
  ]
}
```

硬约束：

- 只描述可听见的非语言声音；不得出现台词、人物姓名、心理活动、音乐、情绪判断或“生成 N 秒”等控制词。
- 一个主要声源一条计划；多个同等独立声源拆条。没有文本依据时宁可不生成。
- `position` 限制为 0–1；`duration_seconds` 大于 0、小于等于 30。短促事件首轮建议 1–5 秒。
- 为保证现有实时播放、WAV 和 MP4 导出不截断尾音，第一期还必须满足：`duration_seconds ≤ 从 position 到本条台词结束的实际可播放秒数 + break_duration`。不满足时缩短、改落点或由用户改成下一句的音效。
- 同一条音效不得覆盖已绑定的用户素材；自动生成默认是“提案”，只有用户确认后才写库。

生成成功后的资产结构应复用现有库，而非重写 schema。例如：

```json
{
  "libraries": {
    "sfx": [
      {
        "id": "sfx_ai_001",
        "name": "AI·玻璃碎裂·line_123",
        "description": "厚玻璃杯在木地板上摔碎……",
        "filename": "ai-glass-break-line_123.wav",
        "assetKey": "sfx_ai_001",
        "volume": 0.55,
        "trimStart": 0,
        "trimEnd": 1,
        "generated": {
          "provider": "moss-soundeffect-v2",
          "prompt": "厚玻璃杯在木地板上摔碎……",
          "seconds": 1.8,
          "seed": 0,
          "requestHash": "sha256:..."
        }
      }
    ]
  }
}
```

关联台词仍使用旧格式：`"sfx": [{"name": "AI·玻璃碎裂·line_123", "position": 0.72}]`。可额外保存 `autoSfxPlan`/`generated` 审计元数据，但它们必须可缺省，且不得替换现有 `sfx` 数组。

### 第二期：跨台词环境声与氛围

适用对象：雨声、森林虫鸣、室内空调底噪、持续人群、远处车流等。MOSS 模型可生成最长 30 秒，却不能用第一期单句锚点正确表达“从第 5 句持续到第 12 句”。

在未设计明确跨度字段前，不要把它偷塞进一个 `position: 0` 的 `sfx`，否则实时播放、离线 WAV、SRT/MP4 和中段续播会出现不一致。第二期需要先定稿以下之一：

1. 在不新增时间轴块类型的前提下，为 `dialogue` 增加可选 `ambienceStarts`/`ambienceStops` 语义，并同步修改实时播放、离线混音与导出；或
2. 把持续声转成可循环/可停止的专用资源，采用与 BGM 同等级的生命周期设计，但不得混同为音乐。

无论选哪种，都需要一份明确的“开始、结束、淡入、淡出、音量、重叠、从中段播放恢复”的规范和 P1 回归样例。这个决定会影响工程 schema、资产恢复和时间轴，因此必须在实施前获得单独确认。

## 调度、交互和失败处理

1. 增加独立 SoundEffect 服务配置（默认 `http://127.0.0.1:8312/v1/moss/soundEffect`）及健康检查；不能混入现有 TTS 配置并按克隆接口误调用。
2. 生成按钮只处理用户勾选的计划项，展示队列位置、当前项目、请求参数、预计时长未知提示和取消状态。服务端 worker 即使浏览器取消也可能继续运行，因此“已停止等待”与“已停止后端计算”必须分开显示。
3. 所有请求串行，且默认不与 TTS 批量生成并发；这是后端共享 GPU 锁的实际要求。
4. 以 `prompt + seconds + 采样参数 + 模型版本` 的哈希识别同一计划，询问用户是否复用已有资产。更换任一输入后必须生成新版本，不能悄悄覆盖。
5. 失败时保留计划和错误类别，不创建空 SFX 库项，不清除用户已有音效；允许修订 Prompt 后重试。
6. 每个成功项均须提供试听、裁剪、音量、重新生成、解除绑定与删除入口。自动生成并不等于自动采用。

## 混音原则

- 前景动作音效只在文本明确发生处出现，初始音量应低于可懂度阈值，最终由试听确定；不设置未经验证的固定 dB 承诺。
- 对白发生时不要用 AI 音效掩蔽关键字。必要时先选择更早/更晚的落点，或降低 SFX 库级 `volume`，而不是修改台词文本。
- 生成的声效不得包含可辨认人声、对白或未经许可的音乐；出现时标为异常，人工重生成或舍弃。
- 在第二期前，持续环境声不与 BGM 自动叠加；避免两个生成模型在同频段互相掩蔽。

## 验收与回归

### 接口与资产

- 用 mock（模拟）8312 和真实本地服务分别验证：请求字段、WAV 返回、超时、500、空音频、取消和连续队列。
- 验证每个成功 WAV 均以稳定 `assetKey` 写入 `UnitaleDB`，刷新、工程导出和工程导入后仍可试听。
- 确认旧工程、旧本地素材和无 `generated` 字段的 SFX 不受影响；不改旧 localStorage 键。

### 时间轴

- 对同一工程分别做单条试听、从中段顺序播放、WAV 导出、MP4 导出，核对音效相对对白的落点、裁剪和音量乘法一致。
- 第一期间只验收在一句台词和其 `break_duration` 内可完整播放的短音效；超出跨度的场景必须被阻止或标记为待第二期，而不是勉强播放。
- 不新增 `sfx` 类型，保留 `dialogue`、`bgm`、`bgImage` 三类类型。

### 质量与治理

- 人工核对每条 Prompt 是否只含听觉事实、是否存在多主声源/人声/无依据音效、时长是否合适、是否遮蔽台词。
- 记录模型版本、参数、种子、生成时间和授权/素材来源。只使用有权生成和分发的内容。
- 涉及根目录单文件实现时运行仓库规定的内联脚本语法检查；涉及资产、schema 或工程传输时运行 P1 fixture 回归。当前工作区缺少 `scripts/validate-p1-regression-fixture.mjs`，实施前必须先确认其权威恢复位置，不能以“脚本不存在”为由跳过。

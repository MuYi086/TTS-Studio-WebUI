# 本地开发与回归

## 正确入口

当前工作台入口是根目录 [`index.html`](../index.html)，使用 Vue 3 CDN 单文件实现；`webUI/` 已废弃。固定工程样例是 [`fixtures/p1-minimal-regression-project-v3.json`](../fixtures/p1-minimal-regression-project-v3.json)。

## 开发命令

```bash
python3 -m http.server 5173
```

打开 `http://127.0.0.1:5173/index.html`。修改单文件脚本后执行语法检查：

```bash
node -e "const fs=require('fs');const html=fs.readFileSync('index.html','utf8');for(const match of html.matchAll(/<script(?:\\s[^>]*)?>([\\s\\S]*?)<\\/script>/g)){if(match[1].trim())new Function(match[1]);}"
```

在仓库根目录校验固定工程结构：

```bash
node scripts/validate-p1-regression-fixture.mjs
```

此脚本只校验 schema（工程结构版本）和内嵌资产格式，不替代浏览器端到端验证。

2. 保持两个键不变再次刷新，确认直接使用已缓存 URL，网络面板不再请求每日背景元数据。

## 最小在线回归

1. 按 [TTS-and-VoiceDesign 接入](TTS-and-VoiceDesign接入.md) 配置可访问的 TTS 服务。
2. 在 Prompt 管理中检查剧本拆分与分析模板的长文本约束：旁白 25–45 个汉字为软目标，按自然语义停顿独立分段，逗号或自然换气处分段时可设置 0.1–0.2 秒 `break_duration`。在“配音与播放”保留默认“关闭可控克隆”运行分析，确认每个 `dialogue` 都是 `ultimate` + `baseline`，且没有 `control_instruction` 或非语言标签；随后选择“开启可控克隆”重新分析，确认只有需要表演控制的台词输出 `controllable`，稳定基线台词输出 `ultimate`。确认括号内自然语言进入 `control_instruction`、括号外正文进入 `text_content`；没有原文明示的笑声、叹气、犹豫音或指定拟声发声时，即使带问号、感叹号或情绪词也必须输出空的非语言标签数组。已有旧版自定义固定模板的浏览器应继续保持固定模式，若要使用新版路由和分段规则请点击“恢复默认”后重新保存自定义模板。
3. 分析角色音色，点击“生成参考文案”，确认结果写入角色卡片的“参考文案”文本框且可以手工编辑。
4. 点击“生成音色”，确认请求只使用文本框中已确认的音色描述和参考文案，并确认音色库中的 `promptText` 与实际提交文本一致；随后快速为两个以上角色点击“生成音色”，确认接口严格按点击顺序一次只发起一项请求、已完成角色立即出现新音色，且排队角色显示“排队中”。
5. 选择已绑定参考音色的台词；VoxCPM2 与 LongCat-AudioDiT 都需填写准确的参考音频文本。确认模型选择器包含 Qwen3-TTS、VoxCPM2、Ming-omni-tts 和 LongCat-AudioDiT，且选中 LongCat 后请求 Base URL 为 `8307`；历史 IndexTTS2 配置不会被自动改到其他模型。
6. 清除一条台词音频后重新生成，确认可播放；刷新后确认仍可恢复。
7. 使用 `8306` VoxCPM2 的固定 `POST /v2/synthesize` 接口时，手动新增台词应为 `ultimate` + `baseline` 且会要求参考文案。默认关闭可控克隆时，点击“一键生成配音”后本次目标台词必须统一为 `ultimate`，请求携带准确的 `prompt_text`，不含 `control_instruction`。选择“开启可控克隆”并运行脚本分析后，明确需要控制表演的台词应为 `controllable` + 非基线档位，确认请求包含 `backend="voxcpm2"`、`clone_mode="controllable"`、`control_instruction` 和 `nonverbal_tags`，明确不含 `prompt_text`，且 `text` 不包含括号指令。切回基线后应恢复极致克隆，并改为发送准确的 `prompt_text`。
8. 为正文明确有叹气、笑声等可听见反应的台词选择一个非语言标签，确认工程字段 `voxcpm_nonverbal_tags` 最多一个值，请求字段为 `nonverbal_tags`，并自动切为 `controllable`、`expressive`、`needs_review=true`。检查 `8306` worker 终端，确认每个 chunk 在调用模型前输出含控制指令、`[tag]` 与正文的最终模型文本，且没有打印参考文案。
9. 在角色音色模型下拉框分别选择 Qwen、MiMo 和 VoxCPM2；VoxCPM2 请求应访问独立的 `8300/v1/voxcpm2/design`，不能出现在 Qwen 请求中。检查 `8300` 后端终端，确认专用 VoxCPM2 VoiceDesign worker 的最终文本为 `(音色描述)正文`，且请求不需要参考音频。
10. 为一条已生成原始音频、且 `emotion` 为官方标签（如 `coldness`）的台词点击“使用Step-Audio-EditX”。确认第一次请求向 `8300/v1/step-audio-editx/edit` 上传当前行原始音频，并发送当前行文本、`edit_type="emotion"` 和相同的 `edit_info`；成功后能独立试听、删除编辑音频，原始音频不受影响，刷新及完整工程导入导出后两者仍可恢复。
11. 在同一条台词保留第一次编辑结果，再连续点击“使用Step-Audio-EditX”两次；确认三次请求的 `prompt_audio` 路径各不相同，第二次及后续请求上传并使用最近一次 EditX 结果，而不是原始音频，且每次成功后最新结果可试听。清除编辑结果后再次点击，确认 prompt 回退到原始音频。
12. 选择 LongCat-AudioDiT 生成一条短台词，确认请求为 `POST 8307/v2/synthesize`，携带 `audio_path`、准确 `prompt_text` 和 `text`，不携带 VoxCPM2 的 `control_instruction` / `nonverbal_tags`；确认返回 WAV 可试听，随后切换其他模型仍按新选择执行。
13. 对同一条新分析出的 `sfx_plan`，确认每项同时有中文 `prompt` 与全英文、只在末尾出现一次 `TrackType: SFX` 的 `prompt_en`，且两者描述同一声音事件。默认选择 Stable Audio 3 Medium 后，在网络面板确认只向 `8313/v1/generate` 发送 `prompt_en` 的英文内容；切换至 MOSS-SoundEffect v2 后，确认只向 `8311/v1/generate` 发送 `prompt` 的中文内容。导入缺少 `prompt_en` 的旧工程后，MOSS 仍可生成；Medium 应显示要求重新分析的错误且不发起请求。
14. 按改动范围补充验证批量生成、顺序播放、停止播放和导出链路。

在线回归依赖实际运行的 `TTS-and-VoiceDesign` 服务、模型权重和本机算力，因此不包含在上述离线自动化记录中。
